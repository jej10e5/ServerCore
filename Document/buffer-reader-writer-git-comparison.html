BufferReader / BufferWriter 추가 분석

GitHub origin/master의 71e7a86과 현재 로컬 작업 트리를 비교한 결과입니다. 로컬에는 패킷 바이트 배열을 순서대로 읽고 쓰는 유틸리티와 이를 사용하는 예제가 추가됐습니다.

핵심 변화

기존에는 buffer[4] 같은 고정 오프셋과 memcpy를 호출부에서 직접 관리했습니다. 변경 후에는 BufferWriter가 쓰기 위치를, BufferReader가 읽기 위치를 관리합니다. 패킷 필드의 선언 순서가 곧 직렬화 순서가 되므로 호출부가 간결해집니다.

현재 확인이 필요한 부분

연산자의 범위 검사가 없습니다. operator>>와 두 operator<<는 FreeSize()를 확인하지 않아 잘못된 패킷이나 용량 계산 오류가 있으면 버퍼 밖을 읽거나 쓸 수 있습니다.

Writer 템플릿 오타가 있습니다. BufferWriter::Write(T* src)가 존재하지 않는 Read(src, sizeof(T))를 호출합니다. 이 오버로드가 인스턴스화되면 컴파일 오류가 발생합니다.

역직렬화 실패가 호출부에 전달되지 않습니다. 문자열 Read() 결과를 검사하지 않고, payload 길이 계산도 unsigned 뺄셈이므로 작은 header.size 입력에서 언더플로가 생길 수 있습니다.

정렬과 표현 형식이 호스트에 의존합니다. reinterpret_cast<T*> 직접 접근은 정렬되지 않은 주소에서 문제가 될 수 있고, 현재 프로토콜은 엔디언과 구조체 패딩을 명시하지 않습니다.

정리

이번 추가분은 패킷 조립과 해석의 반복 코드를 공통 유틸리티로 이동하는 첫 단계입니다. 정상 입력의 예제 흐름은 읽기 쉬워졌지만, 네트워크 입력에 사용하려면 모든 읽기·쓰기 경로의 용량 검증, 실패 전파, 안전한 복사 방식과 프로토콜 바이트 순서를 먼저 확정하는 것이 좋습니다.
